# Creating Pull Requests

- Keep each pull request focused on one coherent change.
- Before opening or updating a pull request, run the applicable checks in `mem:task_completion` and inspect the final Git diff.
- The pull-request description should state the user-visible or architectural change, relevant compatibility/deployment implications, and the checks that passed.
- Do not add release notes or changelog entries unless a task explicitly introduces a replacement release-notes mechanism.
